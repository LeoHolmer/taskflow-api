## Notas de Desarrollo

### Decisiones Arquitectónicas

#### 1. Clean Architecture
Se eligió separar la aplicación en capas independientes para facilitar testing y mantenimiento:
- Presentation (Controllers)
- Application (Services)
- Domain (Entities, DTOs)
- Infrastructure (Repositories, Config)

**Beneficio**: Cambiar la BD o la API sin afectar la lógica de negocio.

#### 2. Soft Delete
Las entidades tienen un campo `deletedAt` en lugar de eliminar registros:
- **Pro**: Se puede recuperar datos accidentalmente eliminados
- **Contra**: Queries más complejas (siempre filtrar `deletedAt IS NULL`)

#### 3. DTOs vs Entities
Se usan DTOs separados de entidades JPA:
- **Pro**: No exponer la estructura interna de BD al cliente
- **Contra**: Mapeo adicional (usando Lombok)

#### 4. Profiles de Spring
Se usan 3 perfiles: `dev` (default), `prod`, `test`:
- **dev**: H2, SQL logging, debug enabled
- **prod**: PostgreSQL, optimized, env vars
- **test**: H2 en memoria, SQL logging
